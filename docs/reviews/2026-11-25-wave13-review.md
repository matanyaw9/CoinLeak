### Must fix

1. `src/core/ledger/paid-back.ts:76` - **a paid-back link outlives the category it explains.** Only `markPaidBack` and `clearPaidBack` ever touch `paid_back_for`. Changing the row's category any other way keeps the link: the category picker and bulk categorize (`queries.ts:354`), and saving a rule that takes over hand-set rows (F45, `rules/queries.ts:156`). Scenario: link a 50 Bit payment to a pizza (Restaurants), then recategorize it by hand as Gifts. The row still shows the coin icon and "Paid back for Pizza Hut" on hover (`category-cell.tsx:67`), and the row menu still offers "Not paid back", which empties the category: the user's Gifts choice is gone. That breaks "user edits win". Fix: any other change to a row's category also sets `paid_back_for = NULL` (one extra column in the `updateTransactions` category branch and in the rule release at `rules/queries.ts:156`), plus a test for each. Related owner question: when the purchase's own category changes, the pay-back keeps the old one, so the 50 still lowers Restaurants while the 100 now sits in Takeout. Should pay-backs follow their purchase?

2. `src/core/ledger/sync-window.ts:23` - **a quick sync can silently skip months for an account that was turned back on.** The quick window starts at the provider's last sync minus 60 days, read from `sync_runs`, which knows the provider but not each account. Scenario: Cal card A is removed from syncing in January (spec 15) while card B keeps syncing. In June the user clicks "Add back" (`remove-sync.tsx:91`; the toast says "A syncs again"). The next Sync asks only from about April, so A's February to April purchases are never downloaded and nothing says so. The same happens after a download that succeeds with no accounts at all: `ingest` still records a run (`ingest.ts:66`) and the next quick sync counts from it. Fix: start from the oldest `accounts.last_synced_at` among the provider's accounts that still sync, minus 60 days (ingest already updates that date for each account it saves and skips removed ones). Trade-off: an account the bank stopped reporting keeps that date old, so its provider's syncs stay full until the user removes it from syncing; slower, but never missing rows. Add the "Add back" case to `sync-window.test.ts`.

### Should fix

1. `src/renderer/src/components/transactions/row-menu.tsx:39` - **Paid back adds a second way to open row dialogs.** Note and cash edit open through `RowMenuActions`, with one dialog on the page (`transactions-page.tsx:148`). Paid back instead adds `EntryDialog`, `useEntryDialog`, a `RowDialog` context and an optional `onSelect`, and renders its dialog inside each row. Costs: the dialog vanishes if its row leaves the list while it is open; its key presses bubble (in React) through the row's parents, which will matter when wave 14 adds list keys (F83 to F86); and `RowMenuButton`'s own slot (`own`, line 104) is dead code, because that button only ever appears inside a row. Fix: add `openPaidBack(row)` to `RowMenuActions` and render one `PaidBackDialog` / `NotPaidBackDialog` on the page, like `noteRow`. The context, the slot and about 40 lines go away.

2. `src/renderer/src/components/transactions/paid-back-dialog.tsx:83` - **Enter can link the wrong purchase right after typing.** The search waits 150 ms and keeps showing the old list while it loads (`placeholderData`). Type "pizza" and press Enter quickly: Enter picks the first row of the previous list (say, the newest coffee) and copies its category. The toast names it and it can be undone, but it is easy to miss. Fix: ignore Enter while `query !== text.trim()` or `candidates.isPlaceholderData`.

3. `REQUIREMENTS.md:128` - **section 5 (Sync) does not mention quick sync.** It still reads as if every Sync downloads all the bank allows. Add a line: after a provider's first sync, Sync asks from the last sync minus 60 days (never before `syncFrom`), "Download everything again" does a full download, and only pending rows inside what was asked for can become gone (spec 32). CLAUDE.md asks to keep REQUIREMENTS true.
